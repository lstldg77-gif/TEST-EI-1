## 3. 주제 선정 이유

**왜 한국사인가**

| 이유 | 설명 |
|---|---|
| 시대가 넓다 | 고조선부터 근현대까지 인물·사건이 고르게 있어 문제를 다양하게 만들 수 있다 |
| 실제로 쓸모 있다 | 한국사능력검정시험처럼 공부할 일이 많아, 게임으로 반복해 풀면 복습이 된다 |
| 4지선다에 맞다 | 인물, 연도, 장소처럼 정답이 명확한 사실 위주라 객관식 형식과 잘 어울린다 |

기본 퀴즈 7개 (시대 순)

| # | 문제 | 정답 |
|---|---|---|
| 1 | 고조선을 건국한 것으로 전해지는 인물은? | 단군왕검 |
| 2 | 고려를 건국한 인물은? | 왕건 |
| 3 | 신라의 삼국 통일을 완성한 왕은? | 문무왕 |
| 4 | 훈민정음을 창제한 조선의 왕은? | 세종 |
| 5 | 임진왜란 때 한산도 대첩을 승리로 이끈 장군은? | 이순신 |
| 6 | 3·1 운동이 일어난 해는? | 1919년 |
| 7 | 대한민국 임시정부가 처음 수립된 도시는? | 상하이 |

**🎤 발표 대본**

> 퀴즈 주제는 한국사로 정했습니다. 이유는 세 가지입니다.
> 첫째, 고조선부터 근현대까지 다룰 시대가 넓어서 인물과 사건을 고르게 섞어 문제를 만들 수 있습니다. 실제로 기본 퀴즈 7개도 고조선 건국, 고려 건국, 신라 삼국 통일, 훈민정음, 임진왜란, 3·1 운동, 대한민국 임시정부까지 시대 순으로 구성했습니다.
> 둘째, 한국사능력검정시험처럼 실제로 공부할 일이 많은 분야라 게임으로 반복해서 풀면 복습에 도움이 됩니다.
> 셋째, 인물이나 연도처럼 정답이 분명한 사실 위주라서 4지선다 객관식 형식과 잘 맞습니다.

## 4. 실행 화면 ① 메뉴와 잘못된 입력

**어떤 입력에도 멈추지 않는 메뉴**

```
========================================
          한국사 퀴즈 게임
========================================
  1. 퀴즈 풀기
  2. 퀴즈 추가
  3. 퀴즈 목록
  4. 점수 확인
  5. 종료
========================================
메뉴를 선택하세요 (1-5):  9
[안내] 1~5 사이의 숫자를 입력해 주세요.
메뉴를 선택하세요 (1-5): abc
[안내] 'abc'은(는) 숫자가 아닙니다. 숫자를 입력해 주세요.
메뉴를 선택하세요 (1-5):
[안내] 입력이 비어 있습니다. 숫자를 입력해 주세요.
메뉴를 선택하세요 (1-5): 4

[안내] 아직 퀴즈를 풀지 않았습니다. 퀴즈를 풀면 최고 점수가 기록됩니다.
```

| 입력 | 처리 |
|---|---|
| ` 9 ` (공백 포함) | 앞뒤 공백 제거 후 처리 → 범위 밖이라 1~5 안내 |
| `abc` | 숫자 아님 안내 후 재입력 |
| Enter (빈 입력) | 빈 입력 안내 후 재입력 |

**🎤 발표 대본**

> 이제 실제 실행 화면입니다. 프로그램을 실행하면 다섯 개의 메뉴가 나옵니다.
> 메뉴는 숫자로 고르는데, 잘못된 입력이 들어와도 프로그램이 멈추지 않도록 처리했습니다.
> 앞뒤에 공백이 있는 9를 넣으면 공백을 지운 뒤 9로 인식하고, 범위가 1부터 5까지라고 안내합니다. abc처럼 숫자가 아닌 값, 그리고 아무것도 입력하지 않고 Enter를 눌러도 안내 메시지를 보여주고 다시 입력받습니다.
> 퀴즈를 풀기 전에 4번 점수 확인을 누르면 아직 기록이 없다고 알려줍니다.
> 이 입력 검증은 read_number라는 메서드 하나에 모아 두어서 메뉴 선택, 정답 입력, 퀴즈 추가 등 숫자가 필요한 모든 곳에서 재사용합니다.

## 5. 실행 화면 ② 퀴즈 풀기

**정답·오답을 바로 알려주고 점수를 기록**

```
퀴즈를 시작합니다! (총 7문제)

[문제 5] 임진왜란 때 한산도 대첩을 승리로 이끈 장군은?
  1. 권율
  2. 이순신
  3. 김시민
  4. 곽재우
정답 번호를 입력하세요 (1-4): 1
  -> 오답입니다. 정답은 2번 '이순신'입니다.

[문제 6] 3·1 운동이 일어난 해는?
  1. 1910년
  2. 1919년
  3. 1945년
  4. 1950년
정답 번호를 입력하세요 (1-4): 2
  -> 정답입니다!
  ...
----------------------------------------
결과: 7문제 중 5문제 정답 (71점)
----------------------------------------
[축하] 최고 점수를 갱신했습니다! (71점)
```

동작 순서

1. 저장된 퀴즈를 차례로 출제
2. 오답이면 정답 번호와 내용 안내
3. 끝나면 100점 만점 점수 계산
4. 최고 점수보다 높으면 갱신하고 저장
5. 퀴즈가 0개면 "먼저 퀴즈를 추가해 주세요" 안내

**🎤 발표 대본**

> 메뉴 1번, 퀴즈 풀기 화면입니다. 저장된 퀴즈를 1번부터 차례로 출제합니다.
> 정답을 고르면 바로 "정답입니다"라고 알려주고, 틀리면 정답이 몇 번이고 내용이 무엇인지 함께 보여줍니다. 예를 들어 5번 문제에서 1번 권율을 고르자, 정답은 2번 이순신이라고 안내했습니다.
> 모든 문제를 풀면 맞힌 개수를 100점 만점 점수로 바꿔 보여줍니다. 이번 실행에서는 7문제 중 5문제를 맞혀 71점이 나왔고, 이전 기록보다 높아서 최고 점수가 갱신되었습니다. 최고 점수는 바로 파일에 저장됩니다.
> 그리고 등록된 퀴즈가 하나도 없을 때는 오류가 나지 않고 먼저 퀴즈를 추가하라는 안내가 나옵니다.
> 참고로 이 퀴즈 풀기 기능은 main이 아닌 별도 브랜치에서 개발해서 병합했습니다.

## 7. 코드 구조

**문제 하나는 Quiz, 게임 전체는 QuizGame**

```
TEST-EI-1/
├── main.py              # 진입점: QuizGame을 만들어 run()만 호출
├── quiz_game.py         # QuizGame 클래스
├── quiz.py              # Quiz 클래스
├── default_quizzes.py   # 기본 한국사 퀴즈 7개
├── state.json           # 실행 데이터 (자동 생성, Git 제외)
└── docs/BRIEFING.md     # 이 발표 자료
```

**Quiz** (`quiz.py`)

| 구분 | 이름 | 설명 |
|---|---|---|
| 속성 | `question` | 문제 (str) |
| 속성 | `choices` | 선택지 4개 (list) |
| 속성 | `answer` | 정답 번호 1~4 (int) |
| 메서드 | `display()` | 문제와 선택지 출력 |
| 메서드 | `is_correct()` | 정답 확인 |
| 메서드 | `to_dict()` / `from_dict()` | JSON 저장·불러오기용 변환 |

**QuizGame** (`quiz_game.py`) — 속성: `quizzes`(Quiz 리스트), `best_score`, `state_file`

| 역할 | 메서드 |
|---|---|
| 실행 · 메뉴 | `run()`, `show_menu()`, `handle_choice()`, `quit()` |
| 입력 처리 | `read_number()`, `read_text()` |
| 게임 진행 | `play()`, `add_quiz()`, `list_quizzes()`, `show_score()` |
| 파일 저장 | `load()`, `save()`, `reset_to_default()` |

**🎤 발표 대본**

> 코드 구조입니다. 클래스는 두 개입니다.
> Quiz 클래스는 문제 하나를 표현합니다. 문제, 선택지 4개, 정답 번호를 속성으로 가지고, 화면에 출력하는 display, 정답인지 확인하는 is_correct, 그리고 JSON으로 저장하고 불러오기 위한 to_dict, from_dict 메서드가 있습니다. `__init__`에서 선택지가 4개인지, 정답이 1에서 4 사이인지 검사해서 잘못된 퀴즈는 만들어지지 않게 했습니다.
> QuizGame 클래스는 게임 전체를 관리합니다. 퀴즈 목록과 최고 점수를 속성으로 들고 있고, 메서드는 역할별로 네 묶음입니다. 실행과 메뉴, 입력 처리, 게임 진행, 파일 저장입니다.
> 처음에는 main.py 한 파일에 모두 있었는데, 기능을 다 만든 뒤 QuizGame을 quiz_game.py로 분리하는 리팩터링 커밋을 했습니다. 그래서 지금 main.py는 게임 객체를 만들고 run을 호출하는 진입점 역할만 합니다.

## 8. 데이터 저장 (state.json)

**state.json 하나에 퀴즈와 최고 점수**

```json
{
  "quizzes": [
    {
      "question": "훈민정음을 창제한 조선의 왕은?",
      "choices": ["태조", "태종", "세종", "정조"],
      "answer": 3
    }
  ],
  "best_score": 71
}
```

| 항목 | 내용 |
|---|---|
| 어디에 | 프로젝트 루트의 `state.json`, UTF-8 인코딩 |
| 언제 | 퀴즈 추가 직후 · 퀴즈 완료 후 · 종료할 때 (Ctrl+C 포함) |
| 왜 JSON | 파이썬의 dict·list와 구조가 같고, 사람이 읽을 수 있는 텍스트라 확인이 쉽다 |
| Git 관리 | 실행마다 바뀌는 개인 데이터라 `.gitignore`에 등록 |

**🎤 발표 대본**

> 데이터 저장 방식입니다. 퀴즈 목록과 최고 점수를 프로젝트 폴더의 state.json 파일 하나에 저장합니다.
> 구조는 quizzes라는 리스트 안에 퀴즈마다 question, choices, answer가 있고, best_score에 최고 점수가 들어갑니다. 아직 한 번도 풀지 않았다면 best_score는 null입니다.
> 한글이 깨지지 않도록 UTF-8 인코딩으로 열고, json.dump에 ensure_ascii=False 옵션을 줘서 파일을 열었을 때 한글이 그대로 보이게 했습니다.
> 저장은 퀴즈를 추가한 직후, 퀴즈를 다 푼 뒤, 그리고 프로그램을 종료할 때 합니다.
> JSON을 고른 이유는 파이썬의 딕셔너리, 리스트와 구조가 거의 같아서 변환이 쉽고, 사람이 메모장으로 열어도 읽을 수 있는 텍스트 형식이기 때문입니다.
> 참고로 state.json은 실행할 때마다 바뀌는 개인 데이터라서 .gitignore에 넣어 GitHub에는 올리지 않았습니다.

## 9. 예외 처리

**비정상 종료 없이 안내하고 복구한다**

| 상황 | 처리 방법 | 사용한 문법 |
|---|---|---|
| `abc` 같은 문자 입력 | 안내 후 다시 입력 | `try` / `except ValueError` |
| 빈 입력, 범위 밖 숫자 | 안내 후 다시 입력 | `if` 조건 + `while` 반복 |
| Ctrl+C, 입력 종료 | 안내 → 저장 → 안전하게 종료 | `except (KeyboardInterrupt, EOFError)` |
| state.json 없음 | 기본 퀴즈 7개로 시작 | `os.path.exists` |
| state.json 손상 | 안내 후 기본 데이터로 복구 | `except (ValueError, KeyError, TypeError)` 등 |
| 파일 쓰기 실패 | 안내만 하고 게임은 계속 | `except OSError` |

손상된 파일로 실행했을 때

```
[안내] 데이터 파일(state.json)을 읽을 수 없습니다: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
[안내] 기본 퀴즈 데이터로 복구합니다.
```

퀴즈 도중 Ctrl+C

```
정답 번호를 입력하세요 (1-4): ^C

[안내] 입력이 중단되었습니다. 데이터를 저장하고 안전하게 종료합니다.
```

**🎤 발표 대본**

> 예외 처리입니다. 과제에서 요구한 상황을 모두 처리했습니다.
> 숫자를 입력해야 하는데 abc 같은 문자를 넣으면 int 변환에서 ValueError가 나는데, try except로 잡아서 안내하고 다시 입력받습니다. 빈 입력이나 범위 밖 숫자는 if 조건으로 걸러내고, while 반복문으로 올바른 값이 들어올 때까지 계속 묻습니다.
> 실행 중에 Ctrl+C를 누르거나 입력 스트림이 끊기면 KeyboardInterrupt나 EOFError가 발생하는데, 이것도 run 메서드에서 잡아서 데이터를 저장한 뒤 정상적으로 종료합니다.
> 데이터 파일이 없으면 첫 실행으로 보고 기본 퀴즈로 시작합니다. 파일 내용이 깨져 있으면, 예를 들어 JSON 문법이 틀리거나 선택지가 4개가 아니면, 안내 메시지를 보여주고 기본 데이터로 복구합니다.
> 실제로 파일을 일부러 망가뜨려서 테스트했고, README에 그 실행 결과도 넣었습니다.

## 10. Git 작업 흐름

**기능 하나에 커밋 하나**

```
* docs: README에 실제 실행 결과 추가
* docs: clone한 저장소에서 README에 clone/pull 실습 내용 추가   ← clone 폴더에서 작업
* docs: README 작성
* refactor: QuizGame 클래스를 quiz_game.py로 분리
* feat: 최고 점수 기록/갱신 및 점수 확인 기능 구현
* feat: 퀴즈 목록 보기 기능 구현
* feat: 퀴즈 추가 기능 구현
* feat: state.json 저장/불러오기 구현
*   Merge branch 'feature/play-quiz' into main
|\
| * feat: 퀴즈 풀기 기능 구현                                  ← 브랜치에서 작업
|/
* feat: 한국사 기본 퀴즈 데이터 7개 작성
* feat: Quiz 클래스 작성
* feat: 메뉴 출력 및 입력 검증 기능 구현
* chore: 프로젝트 초기 설정 (.gitignore, README.md)
```

| 작업 | 사용한 명령 |
|---|---|
| 초기 설정 | `git init`, `git add`, `git commit`, `git push -u origin main` |
| 브랜치 | `git checkout -b feature/play-quiz` → 개발·커밋 → `git checkout main` → `git merge --no-ff feature/play-quiz` |
| clone | 다른 폴더에 `git clone` → README 수정 → `commit` → `push` |
| pull | 원래 폴더에서 `git pull origin main` → 반영 확인 |

**🎤 발표 대본**

> Git 작업 흐름입니다. 위 그림은 git log --graph 결과를 정리한 것으로, 아래에서 위로 시간 순서입니다.
> 프로젝트 초기 설정으로 .gitignore와 README를 만들고 첫 커밋과 push를 했습니다. 그다음 메뉴, Quiz 클래스, 기본 퀴즈 데이터처럼 기능을 하나 완성할 때마다 커밋했습니다.
> 가운데 갈라진 부분이 브랜치 작업입니다. git checkout -b로 feature/play-quiz 브랜치를 만들어 퀴즈 풀기 기능을 개발했고, main으로 돌아와 merge했습니다. --no-ff 옵션으로 병합해서 그래프에 갈라졌다 합쳐진 기록이 남아 있습니다.
> 이후 파일 저장, 퀴즈 추가, 목록, 점수 기능과 리팩터링, README를 커밋했습니다.
> 마지막으로 clone과 pull 실습입니다. 저장소를 다른 폴더에 clone해서 README에 한 줄을 추가하고 push했고, 원래 작업 폴더로 돌아와 pull로 그 변경을 받아와 반영된 것을 확인했습니다.

## 11. 배운 점

| 분야 | 배운 점 |
|---|---|
| Python 기초 | 횟수가 정해진 출제는 `for`, 올바른 입력이 올 때까지는 `while`. 퀴즈는 `list`, 저장 데이터는 `dict` |
| 클래스와 객체 | `__init__`에서 속성을 만들고, `self`로 각 객체의 데이터에 접근. 역할별로 클래스를 나누니 수정이 쉬웠다 |
| 파일 입출력 | `with open`으로 열고 `json`으로 변환. 파일은 언제든 없거나 깨질 수 있어 `try/except`가 꼭 필요하다 |
| Git | 기능 단위로 커밋하면 변경 이력이 그대로 개발 일지가 된다. 브랜치로 main을 안전하게 지킬 수 있다 |

**🎤 발표 대본**

> 이번 과제를 하면서 배운 점을 네 가지로 정리했습니다.
> 첫째 Python 기초입니다. 퀴즈 개수만큼 출제하는 것처럼 횟수가 정해진 경우에는 for를, 올바른 입력이 들어올 때까지 반복하는 것처럼 끝을 미리 알 수 없는 경우에는 while을 쓴다는 차이를 직접 체감했습니다.
> 둘째 클래스입니다. `__init__`에서 객체가 가질 속성을 만들고, self를 통해 각 객체 자신의 데이터에 접근한다는 것을 이해했습니다. 문제 하나와 게임 전체를 다른 클래스로 나누니 기능을 추가하거나 고칠 때 어디를 봐야 할지 명확했습니다.
> 셋째 파일 입출력입니다. 파일은 없을 수도, 깨져 있을 수도 있기 때문에 try except로 처리해야 프로그램이 멈추지 않는다는 것을 배웠습니다.
> 넷째 Git입니다. 기능 하나마다 커밋하니 로그 자체가 개발 일지가 되었고, 브랜치에서 작업하면 main 코드를 건드리지 않고 안전하게 새 기능을 만들 수 있다는 것을 경험했습니다.
